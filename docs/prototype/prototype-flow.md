# 代码型原型流程

本原型围绕一条跨端旗舰流程实现，不把培训业务压缩成固定的单向表单。

## 旗舰主链路

1. 培训管理员在 Web 端输入培训目标、对象、期限、必修内容与高风险约束。
2. Supervisor 将输入拆分为诊断、检索、规划、规则校验、审批、下发、学习、测评和报告节点。
3. Agent 读取授权范围内的组织与员工上下文，检索带版本的企业知识引用。
4. Agent 生成并比较候选方案；管理员可以查看选择理由、编辑部分内容或重新规划。
5. 确定性规则检查必修、高风险知识、权限和正式写入条件。
6. 低风险方案进入待下发；高风险方案在正式写入前进入审批。
7. 审核员查看目标、影响范围、规则触发原因、知识引用和方案差异后作出决定。
8. 审批通过后，培训管理员幂等下发任务。
9. 员工在 Android 端学习部门化课程、查看知识引用并使用智能辅导。
10. 测评按总分和高风险知识点分别判断。
11. 未达标时只补充薄弱知识点，完成补训后进入复测。
12. 完成结果、补训、复测、异常和 Agent 干预进入培训报告与运行轨迹。

## 可切换演示分支

| 场景 | 关键状态与预期行为 |
| --- | --- |
| 正常培训 | 中风险方案可确认后直接进入待下发 |
| 高风险审批 | 高风险规则拦截正式写入，审核员批准后才能下发 |
| 信息不足 | 列出缺失项并暂停，不补造员工或知识信息 |
| 测评未达标 | 首次测评未达标，生成定向补训并进入复测 |
| 知识冲突 | 暂停使用冲突知识，采用保守方案或转人工确认 |
| Agent 失败 | 有限重试、回退到稳定检查点或人工接管 |

演示场景切换只存在于开发/演示模式，不是正式产品能力。

## 责任边界

- Agent 提出方案、执行受控任务、解释依据并根据结果重规划。
- 确定性规则控制权限、状态、风险阈值、客观评分、幂等和发布条件。
- 人工审核高风险写操作、正式制度和异常接管。
- 外部业务系统负责正式数据、任务状态和审计记录。
- 测评结果不得直接转化为绩效、晋升、处罚或岗位任免结论。
